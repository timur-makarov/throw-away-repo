## Request
> `docs/api.md` lists the handlers but not the shape of an error answer. Add it, with one example.

## Why
Callers of the handlers cannot tell from `docs/api.md` what a failed call returns. The convention (AGENTS.md) is `{"status": 4xx, "error": "..."}`, and `api.get_order` already returns `{"status": 404, "error": "no such order"}` for a missing order. Writing it down lets a caller handle errors without reading the code.

## Done Contract
- Check: `grep -q '"status": 404, "error": "no such order"' docs/api.md`
- Check: `grep -qi 'error' docs/api.md && grep -q '"error": "' docs/api.md`

## Out of scope
- Any change to code or tests: the answer shape is already what the code returns.
- Describing handlers that do not exist yet (tickets 2, 6 and others document their own).

## Assumptions
- ASSUMED: the example is the 404 of `api.get_order` with an unknown id, as it is the only error answer the code returns today (shop/api.py).
- ASSUMED: the page states that an error answer has a 4xx `status` and an `error` text, and that handlers do not raise on bad input (AGENTS.md).
