## Request
> Orders should carry a status: `open`, `paid` or `cancelled`, `open` when nothing is said. The summary shows it. The stored shape changes, so this needs a migration next to `migrations/0001_orders.sql`.

## Why
An order has no state today, so nobody can tell an unpaid order from a paid or cancelled one. A status of `open`, `paid` or `cancelled`, defaulting to `open`, lets the summary show where the order stands. The stored shape changes, so a numbered migration comes with it, which makes this ticket PERSON.

## Done Contract
- Check: `python3 -m pytest -q tests/test_orders.py -k status_defaults_to_open`
- Check: `python3 -m pytest -q tests/test_orders.py -k summary_shows_status`
- Check: `grep -Eqi "status.*(open)" migrations/0003_order_status.sql`

## Out of scope
- A handler to change an order's status: the request only asks that orders carry one and the summary show it.
- Validating a status on write, and who may set it (`shop/auth.py` is untouched).
- The CSV export columns do not change (`id,total`).
