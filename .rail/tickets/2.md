## Request
> Customers and products can only be listed. For both we need create, read one, update and delete handlers, with validation of every field (names not empty, a product's price a non-negative number of cents, a customer's email shaped like an email), paging on both lists, a CSV export for each like the orders one, and tests for all of it. `docs/api.md` should describe every new handler.

## Why
Customers and products can only be listed today, so nothing can be added or corrected through the handlers. The whole request (CRUD, validation, paging and CSV for two record kinds, plus tests and docs) is well over the 600-line cap in one ticket, so this ticket is the first slice: create, read one and update for customers, with validation. It is the smallest part that can be checked alone and that the other slices copy.

## Done Contract
- Check: `python3 -m pytest -q tests/test_customers.py -k create_customer`
- Check: `python3 -m pytest -q tests/test_customers.py -k get_customer`
- Check: `python3 -m pytest -q tests/test_customers.py -k update_customer`
- Check: `grep -q 'api.create_customer' docs/api.md && grep -q 'api.get_customer' docs/api.md && grep -q 'api.update_customer' docs/api.md`

## Out of scope
- Delete, paging and CSV export for customers (slice 2).
- Anything for products (slices 3 and 4).
- Changes to `shop/store.py`, `shop/auth.py` or `migrations/`: this slice uses `store.save_customer` and `store.list_customers` only.
- The existing `api.list_customers` answer does not change.

## Assumptions
- ASSUMED: a customer has the fields `id`, `name` and `email`; `name` must be a non-empty string after trimming, and `email` must have the shape `local@domain.tld` (one `@`, no spaces, a dot in the domain).
- ASSUMED: `create_customer` takes the next id itself (the highest stored id plus 1, or 1 when none), because the request names no id source.
- ASSUMED: a successful create answers `{"status": 200, "customer": {...}}`, following the AGENTS.md convention of 200 for success, not 201.
- ASSUMED: bad input answers `{"status": 400, "error": "..."}`; a missing customer answers 404, as `get_order` does.
- ASSUMED: update replaces `name` and `email` together (both are validated), and does not change the id.
- ASSUMED: with no `get_customer` in `shop/store.py`, read one scans `store.list_customers()`. Adding a store function would make the ticket PERSON, so it is left for a later slice.
