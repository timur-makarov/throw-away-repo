## Request
> An admin should be able to change a product's name through the API. A non-admin gets 403, a missing product 404. The stored write goes through shop/store.py.

## Why
Product names can only be set when a product is saved, so fixing a typo or rebranding an item means deleting and re-creating it. Admins need to rename a product in place through the API, keeping its id and price.

## Done Contract
- Check: `python3 -m pytest -q tests/test_products.py -k rename`
- Check: `python3 -m pytest -q`
- Check: `ruff check .`

## Out of scope
- Who may do what stays in shop/auth.py: the handler asks `auth.allowed`, and the roles table does not change.
- The shape of stored products (id, name, cents) does not change, so there is no migration.
- Existing handlers (list_products, delete_product) and their responses do not change.

## Assumptions
- ASSUMED: renaming needs the existing "write" or "delete" action only if admin-only is kept; admins alone are allowed, so the handler checks an action only the admin role holds ("delete" today), or auth.py gains one. shop/store.py is a PERSON path, so a person approves the contract.
- ASSUMED: the new name must be a non-empty string; an invalid name answers 400 with an error.
