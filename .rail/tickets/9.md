## Request
> An admin should be able to change a product's name through the API. A non-admin gets 403, a missing product 404. The stored write goes through shop/store.py.

## Why
Product names can only be set when a product is created; a typo or a rebrand today means deleting and re-adding the product. Admins need to rename one in place, and no one else should be able to.

## Done Contract
- Check: `python3 -m pytest -q tests/test_products.py -k rename`
- Check: `python3 -m pytest -q tests/test_auth.py`
- Check: `python3 -m pytest -q && ruff check .`

## Out of scope
- Changing a product's price (`cents`) or id.
- The shape of existing responses (`list_products`, `delete_product`) and of stored products does not change; no migration.
- What clerks and viewers may do for existing actions (`read`, `write`, `delete`) does not change.

## Assumptions
- ASSUMED: renaming is admin-only, so `shop/auth.py` gains a new `rename` action granted to admin alone, rather than reusing `delete` or the clerk-allowed `write`.
- ASSUMED: `store.py` has no `get_product`, so one is added there (the `_find_customer` list-scan shortcut is not copied); the write reuses `save_product`.
- ASSUMED: an invalid name (not a string or blank) is a 400, checked after 403 and 404, with the name stripped as customer names are.
- ASSUMED: a non-admin gets 403 even when the product is missing, as `delete_product` does.
