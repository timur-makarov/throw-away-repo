## Request
> With no orders the orders CSV export returns an empty string. It should still return the header row, so a spreadsheet import does not fail.

## Why
A spreadsheet import fails on an empty file. The export must always start with the header row, even when the store holds no orders.

## Done Contract
- Check: `python3 -m pytest -q tests/test_export.py -k no_orders`
- Check: `python3 -c "from shop import export, store; store.reset(); assert export.orders_csv().splitlines() == ['id,customer_id,lines,total']"`
- Check: `python3 -m pytest -q tests/test_export.py`

## Out of scope
- The columns, their order and the cent amounts of the CSV do not change (finance relies on them).
- shop/store.py, shop/auth.py and the migrations do not change.

## Assumptions
- VERIFIED: the only caller of export.orders_csv is tests/test_export.py; shop/api.py does not use it (grep found no other caller).
- VERIFIED: shop/export.py already writes the header before the loop, so the fix may be a test only; verify first.
