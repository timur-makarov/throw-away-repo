## Request
> There is no way to remove a product. Add a `delete_product` handler. Only the admin role may use it; `shop/auth.py` decides that, and it may need a small change there. Anyone else gets a 403, and a product that is not there is a 404.

## Why
Products can be listed and saved but never removed. A `delete_product` handler lets an admin remove one. Removing a record has to go through `shop/store.py` (AGENTS.md), which has no delete function, so one is added there; `shop/store.py` is a person path, so this ticket is PERSON.

## Done Contract
- Check: `python3 -m pytest -q tests/test_products.py -k delete_product_admin_removes`
- Check: `python3 -m pytest -q tests/test_products.py -k delete_product_non_admin_is_403`
- Check: `python3 -m pytest -q tests/test_products.py -k delete_product_missing_is_404`

## Out of scope
- `shop/auth.py`: `ROLES` already gives `admin` the `delete` action and `clerk` and `viewer` not, so `auth.allowed(request, "delete")` is enough and no change is made. If a person wants it otherwise, widen the scope by `rail amend`.
- Deleting customers or orders, paging, CSV and docs for products (ticket 2's later slices).
- Any role name in `shop/api.py`: it calls `auth.allowed`, never checks a role itself.

## Assumptions
- VERIFIED: the request is `{"id": N, "role": "admin"}`. `api.get_order` reads `request.get("id")` (shop/api.py:9)
  and `auth.allowed` reads `request.get("role")` (shop/auth.py:6).
- VERIFIED: the permission check comes before the lookup. The request says "Anyone else gets a 403" with no
  exception for missing products, and checking first does not reveal which ids exist. A request with no role
  gets 403 because `auth.allowed` maps a missing role to the empty set (shop/auth.py:6).
- VERIFIED: success answers `{"status": 200}`, per the handler convention in AGENTS.md; `store.list_products`
  reads the same `_PRODUCTS` table the delete removes from (shop/store.py).
- VERIFIED: `shop/store.py` has no delete function today; `delete_product(product_id)` follows its
  `get_`/`save_`/`list_` naming, and a True/False result lets the handler choose 200 or 404 without a second read.
- VERIFIED: ticket 2's split (slice 4, .rail/tickets/2.md:49) names the same overlap and the same rule.

## Look at
- `shop/api.py` `delete_product`: `auth.allowed(request, "delete")` runs before any lookup, so a non-admin or a
  request with no role gets 403 whether or not the product exists. No role name appears in `shop/api.py`.
- A non-integer `id` (None, a string, a list, a bool) answers 404 instead of raising, so the handler never raises on bad
  input (AGENTS.md); without the check a list id would raise `TypeError` inside `dict.pop`.
- `shop/store.py` `delete_product` returns True only when a record was removed. Ticket 2's slice 4 should reuse it.
- `shop/auth.py` is unchanged: `ROLES` already limits `delete` to `admin`.
