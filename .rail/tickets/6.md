## Request
> There is no way to remove a product. Add a `delete_product` handler. Only the admin role may use it; `shop/auth.py` decides that, and it may need a small change there. Anyone else gets a 403, and a product that is not there is a 404.

## Why
Products can be listed and saved but never removed. A `delete_product` handler lets an admin remove one. Removing a record has to go through `shop/store.py` (AGENTS.md), which has no delete function, so one is added there; `shop/store.py` is a person path, so this ticket is PERSON.

## Done Contract
- Check: `python3 -m pytest -q tests/test_products.py -k delete_product_admin_removes`
- Check: `python3 -m pytest -q tests/test_products.py -k delete_product_non_admin_is_403`
- Check: `python3 -m pytest -q tests/test_products.py -k delete_product_missing_is_404`

## Out of scope
- `shop/auth.py`: `ROLES` already gives `admin` the `delete` action and `clerk` and `viewer` not, so `auth.allowed(request, "delete")` is enough and no change is made. If a person wants it otherwise, widen the scope by `rail amend`.
- Deleting customers or orders, paging, CSV and docs for products (ticket 2's later slices).
- Any role name in `shop/api.py`: it calls `auth.allowed`, never checks a role itself.

## Assumptions
- ASSUMED: the request is `{"id": N, "role": "admin"}`, like `get_order` plus the `role` key that `auth.allowed` reads.
- ASSUMED: the permission check comes before the lookup, so a non-admin gets 403 even for a product that does not exist, and a request with no role gets 403.
- ASSUMED: success answers `{"status": 200}` and a later `list_products` no longer shows the product.
- ASSUMED: the new store function is `delete_product(product_id)` returning True when a record was removed and False otherwise.
- ASSUMED: ticket 2's slice 4 also needs `store.delete_product`; whichever merges first leaves the other to reuse it.
