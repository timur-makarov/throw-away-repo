## Request
> Codes are already stored (`store.save_code`, `store.get_code`) but nothing uses them. An order with a `code` field should have its total reduced by that percent, rounded down to the whole cent, in the order summary and in the CSV export. An unknown code changes nothing.

## Why
Discount codes are stored but never used. Applying them in `orders.total`, which both `orders.summary` and `export.orders_csv` call, makes the summary and the CSV agree. It waits for ticket 4 because both change `orders.total`, and the discount applies to the total that ticket 4 makes an integer.

## Done Contract
- Check: `python3 -m pytest -q tests/test_orders.py -k discount_code_reduces_total`
- Check: `python3 -m pytest -q tests/test_orders.py -k unknown_code_changes_nothing`
- Check: `python3 -m pytest -q tests/test_export.py -k discount_code`

## Out of scope
- `shop/store.py`: `get_code` and `save_code` are used as they are.
- Creating or validating codes, expiry, and one-use limits.
- The line amounts: only the order total is discounted, after the lines are summed.

## Assumptions
- VERIFIED: the work does not rest on a percent being a whole number. Checked: `store.save_code` stores any value
  (shop/store.py), so the discount is computed with `Decimal(str(percent))` and floored, which is exact for 12.5 as well
  as 25. Values outside 0 to 100 are not handled: validating codes is out of scope in this ticket.
- VERIFIED: the discounted total rounds down to the whole cent with no float involved (AGENTS.md). For a whole percent
  the Decimal floor equals `total * (100 - percent) // 100`; the tests pin both a whole and a fractional result.
- VERIFIED: an order without a `code` key, or with an unknown code, keeps its total. Checked: `store.get_code` is
  `_CODES.get(code)`, which returns None for an unknown code.
- VERIFIED: the discount lives in `orders.total`, so the summary and the CSV need no change of their own. Checked:
  `orders.summary` (shop/orders.py:20) and `export.orders_csv` (shop/export.py:12) both call `orders.total`.

## Look at
- `shop/orders.py` `total`: the discount applies once to the summed lines, then floors with Decimal, so a fractional
  percent such as 12.5 stays exact; the "after lines are summed" test fails if it is applied per line.
- An unknown code and no code both leave the total as it was; that test already passed before this change and pins it.
- A percent outside 0 to 100 (for example 150) gives a negative total; validating codes is out of scope.
